# Portable sourcebook set

These three book blueprints turn the research corpus into semester-ready
readers. They are written as separable Markdown units so they can be reviewed
here, expanded independently, and later moved into an Ethical Tech CoLab
publishing repository.

| Sourcebook | Central question | Best semester use |
| --- | --- | --- |
| [Power and the Human Person](book-01-power-and-the-human-person.md) | What makes technological power legitimate? | Moral foundations, dignity, rights, lifecycle accountability, humanitarian AI |
| [Plural Technology and Democratic Agency](book-02-plural-technology-and-democratic-agency.md) | How can digital systems support cooperation across difference? | Digital democracy, participation, mechanism design, public infrastructure |
| [Governing AI Futures](book-03-governing-ai-futures.md) | How should institutions act under radical uncertainty? | Forecast literacy, scenario scrutiny, frontier governance, multilateral design |

## Editorial status

These are **sourcebook blueprints**, not finished textbooks. Each contains:

- a complete argument and chapter sequence;
- primary-source pathways;
- chapter abstracts;
- seminar questions;
- studio work;
- cautions about evidence and attribution;
- a concrete expansion brief.

The blueprints avoid reproducing long source passages. A finished edition
should retain links, use short quotations under the relevant source terms, and
add properly licensed figures or original diagrams.

## Shared editorial rules

1. Put epistemic labels beside forecasts and scenarios.
2. Preserve the theological foundation of religious sources when translating
   them for a plural classroom.
3. Distinguish participation from decision authority.
4. Treat implementation cases as situated evidence, not universal proof.
5. Name the institution expected to act.
6. End each chapter with a testable design task, not only reflection.
7. Include a challenge reading that could change the chapter's conclusion.
8. Version the book and retain a correction log.

## Suggested publishing metadata

Each migrated book should add:

- title, subtitle, author/editor, and edition date;
- canonical repository and public reader URL;
- content license;
- source access date;
- correction and contribution process;
- a statement distinguishing the editor's synthesis from source positions.
